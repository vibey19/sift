# Ways Sift produces a wrong cleaned CSV

Everything below was probed against the code rather than imagined. "Confirmed"
means it was reproduced; "unverified" means it follows from the design but has
not been run.

Ordered by how badly it fails, not how hard it is to fix. The worst failures are
the quiet ones: a file that comes back looking clean and is wrong.

---

## Tier 1 — silently produces wrong data

The output looks finished. Nothing warns anyone. These are the ones that would
embarrass the project in front of an examiner.

| # | Fault | Evidence |
|---|-------|----------|
| 1 | **Browser and server disagree about column names.** Server sees `a, a.1, b`; browser sees `a, a, b`. Blank names: `Unnamed: 1` vs `column_2`. Padded names: server keeps `' a '`, browser trims to `'a'`. Every fix naming such a column silently does nothing — `replay` hits `if (col == null) break` and moves on. | confirmed |
| 2 | **Semicolon, pipe and colon delimiters.** The server only sniffs tab vs comma, so `a;b` parses as one column. The browser *does* detect `;`, so the two halves disagree about the entire shape of the file. | confirmed |
| 3 | **Ambiguous dates.** When no day exceeds 12, `03/04/2023` is month-first by assumption. Half of all such files are wrong, with no warning. | confirmed |
| 4 | **C5 merges case-sensitive values.** `BRCA1` and `brca1` are collapsed. Gene symbols, currency codes, base64, hashes and case-sensitive keys are all corrupted this way. | confirmed |
| 5 | **C11 blanks a legitimate `N/A`.** In a "reason for return" column, "N/A" means not applicable and is a real answer. At 40% of the column it is still blanked. | confirmed |
| 6 | **D1 removes genuine repeated events.** Forty identical coffee sales with no id column are one row after dedupe. Identical does not mean duplicated. | confirmed |
| 7 | **C13 fires on a coincidence.** With few distinct values, `c = a * b` can hold across every observed row by chance. Support of 36 rows was enough. | confirmed |
| 8 | **Units and currencies are erased.** `10 kg` and `10 lb` both become `10`. `$100` and `€100` both become `100`. The number survives, the meaning does not. | confirmed |
| 9 | **`45%` becomes `45`, not `0.45`.** Defensible, but it is a silent semantic choice and the opposite convention is common. | confirmed |
| 10 | **Integers above 2^53 lose precision on export.** `9007199254740993` comes back as `...992`; a 19-digit id becomes `1234567890123456800`. JavaScript numbers cannot hold them. | confirmed |
| 11 | **Leading zeros die if a column is ever reformatted.** `007` → `7`. Currently safe because such columns type as `id_like`, but one inference change away from data loss. | confirmed |

## Tier 2 — produces obviously unusable output

Bad, but visible. Nobody ships these by accident.

| # | Fault | Evidence |
|---|-------|----------|
| 12 | **Title or metadata rows above the header.** Header becomes `Report`, `Unnamed: 1`. Standard in exported spreadsheets. | confirmed |
| 13 | **Comment lines** (`# generated by ...`) are treated as the header. | confirmed |
| 14 | **A totals row at the bottom** is an ordinary row, and its numbers enter every statistic. | confirmed |
| 15 | **Durations `14:30:00` are read as datetimes**, not as elapsed time. | confirmed |
| 16 | **An empty file raises** rather than returning a sentence. Handled as a 400, but the message is a pandas message. | confirmed |

## Tier 3 — missing capability

Not wrong, just absent. Each one is a class of file Sift cannot help with.

| # | Gap |
|---|-----|
| 17 | Non-English sentinels: `unbekannt`, `inconnu`, `desconocido`, `無し`. |
| 18 | Encoding: UTF-16, Latin-1, and mojibake (`Ã©` for `é`) are neither detected nor repaired. A non-UTF-8 upload is silently mangled by the browser's decoder. |
| 19 | Multi-row headers, merged cells, pivoted layouts. |
| 20 | Fuzzy entity matching: `Acme Inc` / `ACME, Inc.` / `Acme Incorporated` are three categories. |
| 21 | Cross-field rules: ship date before order date, postcode not in city, total not matching a sum by group. |
| 22 | Wide files: the arithmetic check gives up above 10 numeric columns; columns cap at 200. |
| 23 | Long text: no truncation, HTML stripping, or unicode normalisation. |

## Tier 4 — scale and interface

| # | Issue |
|---|-------|
| 24 | 4.5MB request limit, roughly 30–50k rows. Above that the file is refused. |
| 25 | With a label column, the audit takes 15–33s on 10k rows. Feels broken and may exceed a serverless timeout. |
| 26 | Near-duplicate detection is skipped above 20k rows. |
| 27 | Fix labels are counted before earlier fixes run: C1 says 40 cells, then C11 blanks 20 more and the fill touches all 60. The number shown is a lower bound, not a count. |
| 28 | Nothing prompts a re-audit after fixes, so the issue list on screen describes the file as it arrived. |
| 29 | The benchmark's reference files were written by the same person who wrote the tool. |

## Order of work

1. **#1 and #2 together** — one shared parsing contract. Everything else is
   built on the assumption that both halves see the same table, and right now
   they do not.
2. **#3, #5, #6, #4** — stop guessing. Where the answer is genuinely ambiguous,
   the fix belongs in the "your call" list rather than the one-click list.
3. **#12, #13, #14** — header and footer detection.
4. **#8, #9, #10** — preserve what cannot be represented: keep the unit, keep the
   original string for large integers, say which convention was used for percent.
5. Everything else.
